PostgreSQL 连接问题汇总（Homebrew 安装）
==========================================


问题一：FATAL:  role "postgres" does not exist
----------------------------------------------
【现象】
  psql -U postgres -h localhost
  报错：FATAL:  role "postgres" does not exist

【原因】
  Homebrew 安装的 PostgreSQL，默认超级用户是当前 macOS 用户名，
  不是传统的 "postgres"。

【本机信息】
  系统用户名：mac
  默认超级用户：mac


问题二：FATAL:  database "mac" does not exist
---------------------------------------------
【现象】
  psql -U mac -h localhost
  报错：FATAL:  database "mac" does not exist

【原因】
  psql 默认会连接一个"与用户名同名"的数据库，但 Homebrew 安装后
  并没有自动创建这个数据库。系统默认存在的数据库叫 "postgres"，
  需要用 -d 参数显式指定。


【正确连接方式】
------------------------------------------------------------
  psql -U mac -d postgres -h localhost
------------------------------------------------------------

  参数说明：
    -U mac          指定用户名为 mac（默认超级用户）
    -d postgres     指定连接 postgres 系统数据库
    -h localhost    通过 TCP 连接本地服务器（省略则走 Unix socket）


【后续可选操作】
------------------------------------------------------------
1. 创建与用户名同名的数据库（这样以后直接 psql -h localhost 就能连）
------------------------------------------------------------
  先连接进去：
    psql -U mac -d postgres -h localhost

  执行 SQL：
    CREATE DATABASE mac OWNER mac;

  退出后直接用下面命令即可连接：
    psql -h localhost

------------------------------------------------------------
2. 创建 postgres 超级用户（兼容传统习惯）
------------------------------------------------------------
  先连接进去：
    psql -U mac -d postgres -h localhost

  执行 SQL（带密码）：
    CREATE ROLE postgres WITH SUPERUSER CREATEDB CREATEROLE LOGIN PASSWORD '你的密码';

  或不带密码：
    CREATE ROLE postgres WITH SUPERUSER CREATEDB CREATEROLE LOGIN;

  （可选）同时创建 postgres 数据库：
    CREATE DATABASE postgres OWNER postgres;

  之后就可以用 postgres 用户连接：
    psql -U postgres -h localhost


问题三：Navicat 创建数据库报错 column d.datlastsysoid does not exist
------------------------------------------------------------------
【现象】
  在 Navicat 中新建数据库时报错：
  ERROR:  column d.datlastsysoid does not exist
  LINE 1: ..., 'pg_database') AS comment, t.spcname, d.datacl, d.datlasts...

【原因】
  PostgreSQL 17+ 移除了系统表 pg_database 中的 datlastsysoid 列，
  但旧版本的 Navicat 在查询数据库列表时仍在使用这个字段，
  导致兼容性错误。PostgreSQL 18 同样存在此问题。

【解决方案】
  方案一：升级 Navicat 到最新版（推荐）
    Navicat 16.3+ / 17+ 版本已修复对 PostgreSQL 17/18 的兼容问题。
    检查更新：Navicat 菜单 -> Check for Updates

  方案二：用 SQL 命令手动创建数据库（临时方案）
    在 Navicat 的查询编辑器中直接执行 CREATE DATABASE 语句，
    绕过图形界面的 bug：
      CREATE DATABASE mydb OWNER mac;

  方案三：降低 PostgreSQL 版本
    如果必须使用旧版 Navicat，可以改用 PostgreSQL 16 或更早版本：
      brew install postgresql@16
      brew services stop postgresql@18
      brew services start postgresql@16

  方案四：使用其他兼容的客户端
    - DBeaver（免费开源，更新积极）
    - pgAdmin 4（官方工具，完全兼容）
    - TablePlus


【常用 PostgreSQL 命令备忘】
  \l                 列出所有数据库
  \du                列出所有角色/用户
  \c 数据库名        切换数据库
  \dt                列出当前数据库的表
  \q                 退出 psql


【Homebrew PostgreSQL 相关命令】
  brew services start postgresql@18    启动服务
  brew services stop postgresql@18     停止服务
  brew services restart postgresql@18  重启服务
  brew services list                   查看所有 brew 服务状态
  psql -V                              查看 psql 版本
